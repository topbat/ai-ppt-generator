# Langfuse 接入与 LLM 指标展示实施方案

**目标：** 为标准 PPT 流水线和 PPT-MASTER 提供可追溯的模型用量记录、Langfuse 观测及中文指标页面。

**架构：** 业务执行 → 独立观测模块 → 本地 observation 表 + Langfuse 异步 SDK。项目页面通过受保护的 FastAPI 接口读取本地统计与 Langfuse Metrics API；两种来源明确分开，避免重复累计。

**技术栈：** Python / FastAPI / SQLAlchemy / Celery / OpenAI SDK / Langfuse SDK，React / TypeScript / Ant Design。

执行方式：按 executing-plans 技能逐项执行。用户已授权方案、任务拆解和连续执行，无需逐阶段再次确认。使用隔离工作区带入当前未提交修复；完成后仅同步本次变更，检查源文件没有并发修改。不提交或推送 Git，不改现有部署数据。

## 一、方案选择

1. 只用 Langfuse 看板：接入快，但任务详情与项目页面割裂。
2. 本地指标 + Langfuse 详细追踪（采用）：本地显示已记录数据，Langfuse 提供调用链和聚合查询。Langfuse 断连不影响生成与本地查看。
3. 完全自建观测平台：维护成本高，本次不采用。

为了控制正文采集、请求计数与异常隔离，采用 Langfuse 显式 generation/span 上报，而不是仅替换 OpenAI import。标准网关统一调用方法覆盖视觉路径。 SDK 底层自动重试关闭，由现有显式重试链负责，使一个观测事件对应一次 SDK HTTP 请求尝试。

## 二、数据模型与指标口径

- 新增 `llm_observations` 表，不修改旧表结构；`create_all` 可创建新表，原 `llm_calls` 保留。
- 标准调用：每个实际请求记录唯一事件 ID、稳定任务 Trace ID、job 主键、stage、task_type、provider、model、mode、attempt、fallback、输入/输出/缓存 Token、请求耗时、排队耗时、状态、错误类别。
- PPT-MASTER：记录每次 CLI 运行的汇总事件，标记 `agent_run`；不把轮次或汇总冒充逐请求数据。Claude 读取最终 usage 与成本；Codex 累加 turn.completed usage；恢复运行分别记录并累计。
- 未返回用量或费用时使用 null；模型费用仅在配置每百万 Token 单价且相关 usage 完整时估算，明确标记估算。供应商费用标记 reported。
- 重试次数指同一逻辑调用首个请求之后的实际尝试；fallback 为切换供应商/模型的尝试。
- 同一任务重试仍关联同一 Trace；每次实际执行用新的 event/span ID，避免覆盖真实消耗。
- 标准请求和 Agent 运行分别统计，调用成功率与 PPT 交付成功率不混为一谈。旧 `llm_calls` 不回填伪造 Trace，页面标注新采集范围。
- 非流式请求不展示虚构首 Token 延迟。时间窗口按 UTC，支持最近 1–90 天、引擎、模型、任务过滤；详情分页，汇总不受分页影响。

## 三、第一阶段：采集与调用链

### 任务 1：基础观测、配置和回归测试

文件：`backend/app/observability.py`、`backend/app/models/models.py`、`backend/app/core/config.py`、`backend/requirements.txt`、`backend/tests/test_observability.py`。

先写并运行失败测试：关闭上报仍能本地记录、缺失 usage 保持 null、稳定 Trace 标识、费用未知/估算、上报异常不覆盖业务异常、默认不传正文。随后实现并复验。

### 任务 2：标准请求与阶段关联

文件：`backend/app/ai/gateway.py`、`backend/app/pipeline/orchestrator.py`、两处视觉调用 stage、`backend/app/worker.py`、`backend/app/main.py`。

在网关实际请求边界记录 generation，分开排队时间；参数兼容重试单独记账；视觉路径统一入口。阶段 span 及线程上下文传递保证并发调用归属正确；Worker 子进程独立初始化，退出刷新。验证成功、异常、过滤拒绝、重试及视觉路径。

## 四、第二阶段：页面与 Agent 适配

### 任务 3：PPT-MASTER usage 适配

文件：`backend/app/pptmaster/runner.py`、`backend/app/pptmaster/service.py`、`backend/tests/test_observability.py`。

先测试 Claude usage、Codex 多轮累加、续跑总量和缺失数据，再实现。每次 runner.run 使用独立事件；正常、超时、取消保留已知消耗。Mock 不进入真实用量统计。

### 任务 4：统计接口与访问控制

文件：`backend/app/api/metrics_api.py`、`backend/app/main.py`、新增测试。

提供 `/api/v1/metrics/summary`、`/observations`、`/remote`；先验证访问令牌，未配置时返回明确不可用状态。后端限制时间范围和分页，构建固定结构远端 query；不开放任意 URL 或任意查询代理。远端查询短超时、有界缓存；错误信息不包含凭据。

项目目前无完整用户身份系统，本次使用独立 `METRICS_ACCESS_TOKEN` 保护指标接口，不声称具有租户级权限。前端令牌仅保存在当前页面内存，Langfuse 密钥不进入浏览器。

### 任务 5：中文指标页面与任务面板

文件：`frontend/src/pages/LlmMetrics.tsx`、`frontend/src/components/JobUsage.tsx`、`frontend/src/api/metrics.ts`、`frontend/src/App.tsx`、两种任务详情。

复用 Ant Design；提供访问令牌输入、时间与模型/引擎过滤、调用量/Token/费用/延迟卡片、日趋势、模型汇总、分页明细，以及 Langfuse 聚合区域。任务面板复用统计接口按业务 ID 查询；空值显示未知，错误与空状态明确。处理请求乱序和刷新状态。

### 任务 6：配置文档与验收

更新 backend/deploy `.env.example` 和中文运维文档。配置 Langfuse 开关、地址、公钥/私钥、浏览器访问地址/项目 ID、正文采集开关、访问令牌和可选模型单价。

Langfuse 使用已有 Cloud 或独立自托管实例，不默认向当前 Compose 增加 ClickHouse 等基础设施。SDK/服务端版本需匹配；Metrics 使用当前官方 v2 API，不支持的服务端显示明确失败。

浏览器检查桌面与窄屏、未授权/空数据/示例数据状态。通过 SDK 测试传输验证序列化与无正文数据；使用模拟远端验证 Metrics 查询与失败降级。若无真实 Langfuse 凭据，准确交付“实现及模拟集成已验证，真实实例待配置”，不宣称真实上报已成功。
