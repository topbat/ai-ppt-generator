# AI PPT 自动生成系统 — UI 规划与原型

> 版本：V1.0
> 日期：2026-08-13
> 技术基线：React 18 + Ant Design 5 + TypeScript，桌面 Web 优先（≥1280px），Nginx 容器部署
> 关联文档：[01-PRD.md](01-PRD.md)、[03-IMPLEMENTATION.md](03-IMPLEMENTATION.md)

---

## 1. 设计原则

1. **任务流优先**：产品核心是"一次生成任务"，UI 围绕"新建 → 观察进度 → 预览/下载 → （失败）重试"主链路组织；
2. **边生成边看**：进度不是黑盒进度条，页面生成一页展示一页（先内容卡片、后缩略图）；
3. **失败即解释**：任何失败状态必须同屏给出"失败阶段 + 原因 + 建议动作 + 重试按钮"；
4. **过程可追溯**：阶段耗时、事实来源、自动兜底记录都有查看入口，但默认收纳，不干扰主流程；
5. **少配置**：新建任务只暴露 5 项核心输入，高级项收进折叠面板。

---

## 2. 信息架构

```text
App
├── /jobs                    任务列表（首页）
├── /jobs/new                新建生成（三步向导）
├── /jobs/:id                任务详情
│     ├── 进行中视图         （进度 + 边生成边看）
│     ├── 成功视图           （预览 + 下载 + 报告）
│     └── 失败视图           （原因 + 重试）
├── /templates               模板库（上传/管理/预览）
└── /admin                   管理端（V1 简版：任务统计、耗时分析）
```

顶部导航常驻：`任务列表 | 新建生成 | 模板库`，右侧为系统状态点（API/Worker 健康）。

---

## 3. 核心流程

```text
新建生成（3 步向导）
  Step1 上传模板(可选,默认系统模板)
  Step2 上传主说明文档 → 立即后台解析预检
  Step3 参数(页数/模式/密度) → 提交
        │
        ▼
任务详情-进行中（SSE 实时进度）
  阶段清单 + 总进度 + 页面缩略图流式出现
        │
   ┌────┴──────────────┐
   ▼                   ▼
 需要用户决策        执行完成
 (冲突/页数预算/       │
  内容不足弹窗)     ┌──┴──┐
   │               ▼     ▼
   └──继续──────▶ 成功   失败
                   │      │
                   ▼      ▼
              预览/下载  原因+重试
```

关键交互约定：

- 提交后立即跳转任务详情页，不停留在向导；
- 决策类中断（事实冲突/页数预算/内容不足）以**阻塞式弹窗**出现在任务详情页，10 分钟未响应按默认策略继续（弹窗中明示默认策略与倒计时）；
- 进度通道：SSE，断线自动降级为 3s 轮询。

## 5. 组件状态规范

### 5.1 任务状态 → UI 表现

| 状态 | 列表徽标 | 详情页视图 | 可用操作 |
|---|---|---|---|
| queued 排队中 | 灰点 "排队中" | 进度页（0%，显示队列位置） | 取消 |
| running 生成中 | 蓝点 + 百分比 | 进度页（SSE 实时） | 取消 |
| waiting_user 待确认 | 橙点 "待确认" | 进度页 + 阻塞弹窗 | 做出选择/取消 |
| succeeded 成功 | 绿点 + 质量分 | 预览页 | 预览/下载/重新生成/看报告 |
| failed 失败 | 红点 + 错误码 | 失败页 | 断点重试/换输入重试/看日志 |
| canceled 已取消 | 灰点 "已取消" | 简版详情 | 重新生成 |

### 5.2 进度推送协议（前端约定）

- SSE 事件类型：`stage_update`（阶段状态/耗时）、`page_done`（第 n 页内容就绪，携带内容卡片 JSON）、`thumbnail_ready`（第 n 页缩略图 URL）、`decision_required`（决策弹窗 payload）、`job_done`、`job_failed`；
- 断线重连：3 次失败后降级轮询 `GET /jobs/:id`（3s 间隔），恢复后切回 SSE；
- 所有时间均由后端下发（服务器时间），前端只做展示，避免时钟偏差。

### 5.3 错误文案规范

- 结构固定：`[一句话现象] + [原因] + [建议动作]`，不出现堆栈/内部术语；
- 错误码始终展示（便于报障），完整映射表见实现方案 §7.3；
- Warning 类信息统一收进"质检报告"页签，不打断主流程。
